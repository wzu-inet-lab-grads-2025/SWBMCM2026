# 第四问首轮实验的共同口径

初始计划统一读取 `experiments/b/snapshots/q2_numerical/summary.json` 的 `q22.jobs`。这是第二问已复核的名义可行方案，三项任务的最晚开始时刻为 10.352118591 s。扰动在 5 s 发生。原题要求与讨论中的断联范围见[验收清单](../../../docs/b-acceptance.md)和[建模笔记](../../../docs/modeling-notes.md)。

首轮采用以下可比较的约定。原计划在 0 s 完整下发，断联期间可继续执行已下发的后续任务。新指令在恢复时或之后生效。调度策略在恢复前无法使用未来的恢复时刻。某车在 5 s 故障会立即退出。5 s 前已开始观测的告警锁定并保留得分，健康搭档按原观测结束时刻完成该次占用并复位。已派出、尚未开始观测的车辆可以接收改派指令。移动必须从当时所在位置出发，云台在行驶期间保持正东水平。对同刻事件先处理故障等扰动，再评估观测能否开始。60 s 恰好共同开始计为成功。

保持原计划的策略执行原车对、原站位和每车的任务顺序。新增告警计入分母，保持策略没有为它预定席位。故障伙伴无法到达时，未开始的原任务保持未完成，等待该任务的车辆按原任务依赖继续等待。重新调度可重新安排剩余健康车辆及未锁定任务。

命题人已在指定答疑频道确认，绝对恢复时刻为 `(5,30] s`，对应断联时长为 `(0,25] s`。主情景取 10 s 和 30 s，题内扩展取 8 s 和 20 s。35 s 单列为域外压力测试。关于断联期间如何执行已下发的后续任务，首轮仍按上文的完整下发约定回放两种策略。[答疑原文及依据](../q4_scenarios/CLARIFICATION.md) · [126 项主情景](../q4_scenarios/manifest.json)

## 情景与事件数据

共享情景清单用 JSON 对象 `{"scenarios": [...]}`。各行字段为 `id`、`new_alert`（`null` 或 `[theta_deg, range_m, altitude_m]`）、`failed_vehicle`（`null` 或 `V1` 至 `V5`）、`recovery_s`（`null` 或绝对时刻）。原题未给新增告警的位置分布，按情景分别比较。故障身份等权。

逐情景结果记录 `scenario_id`、`policy`、`N`、`k`、`eta`、`t_last_s`、`jobs` 和 `events`。`jobs` 是一个对象，T1、T2、T3 以及有新增时的 T4 分别对应包含 `start_s` 和 `vehicles` 的对象，未开始用 `null` 和空列表。`events` 是逐车记录列表，每项至少有 `vehicle`、`target`、`kind`、`t0`、`t1`，时间单位为秒。事件种类包含 `drive`、`slew`、`wait`、`observe`、`reset`、`idle`、`fail`；瞬时事件两端时刻相同。用 `drive` 的 `path` 折线、观测站位和有效发令时刻支持独立复核。多情景文件可按 JSON Lines 输出，每行一份结果。输入、复跑脚本和精简证据保存在各实验目录，详细回放可写到 `runs/b/`。

两种策略在结果顶层声明 `rotation_model=independent_rate_limited_axes`。转向或复位从事件开始时的真实姿态出发，两轴各自以 30°/s 转动，先到目标的轴保持该角度。若命令在中途打断转向，日志记录原目标角和中断时的实际角度。
