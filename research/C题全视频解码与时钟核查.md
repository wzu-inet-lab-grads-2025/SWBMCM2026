# C 题全视频解码与时钟核查

69 条官方记录的 **184 个 MP4 全部从首帧解码至文件末尾，共 178,512 个视角帧**。每个文件的解码帧数、带 PTS 的视频包数、容器声明帧数和对应轨迹行数四者相等。Pro、Standard 共 104 路相机的 **134,596 行旁车时间戳**与轨迹逐行相等，精确到整数纳秒。视频 PTS 与轨迹采用的时间刻度有细微差异，对齐首帧后，任一行最大绝对偏差为 **1.740 毫秒**。[时钟汇总](c_full_audit/video_clock.csv)

## 展示时间与原始时钟

在解码器输出后、缩放前，用 `showinfo` 读取按展示顺序到达的帧序号和整数 PTS。每个文件保留 FFmpeg 报出的有理数 `time_base`，逐帧验证其 PTS 与按展示时间排序的包 PTS 完全相同。184 个文件的首帧 PTS 均为零。解码使用 `-copyts -vsync 0` 保留时间戳与输出帧数，避免按目标帧率补帧或丢帧。[核查脚本](../experiments/c_full_video_decode.py)

以每路视频的首帧、每条轨迹的首行各自为零，按原始行序计算 **Δ = 相对 PTS − 相对轨迹时间**。Demo 使用 Parquet `timestamp` 的原存储值，逐行验证 `frame_index` 自 0 连续递增。Pro、Standard 先在整数纳秒域内相减，然后换算成秒。五张位姿表及手部质量表的 `header.ts` 按行核对一致，以右手表为共同参照。旁车另行计算相对 PTS 差，并用原始绝对纳秒核对 `video_timestamp_ns` 与 `header.ts`。下表先将 Δ 四舍六入五成双到最近整数纳秒，再取分位数和严格超阈值计数。分母按视角逐帧加权。[逐来源、划分和视角的时钟统计](c_full_audit/video_clock.csv)

| 来源 | Δ 范围（µs） | 绝对偏差 P50 / P95（µs） | 超 10 µs 的行 | 超 1 ms 的行 | 配对行分母 |
|---|---:|---:|---:|---:|---:|
| EgoDemo | −1.780 至 +1.780 | 0.191 / 1.526 | 0 | 0 | 43,916 |
| EgoPro | −819 至 +509 | 239 / 600 | 68,532 | 0 | 70,568 |
| EgoStandard | −1,740 至 +0.001 | 479 / 1,341 | 61,906 | 12,820 | 64,028 |
| 全部 | −1,740 至 +509 | 175 / 1,118 | 130,438 | 12,820 | 178,512 |

- **固定帧间隔。** 每个文件内部所有相邻 PTS 的整数 tick 差恒定，其倒数换算的帧率均与容器 `r_frame_rate` 相等。Demo 有 25、29.999、30、30.003 fps 四种，Pro 约 29.654232–30.012906 fps，Standard 有 25 和约 30.000300 fps 两种。184 个文件的所有非末包，其持续时间均等于至下一帧的展示间隔。同一条 Pro 记录的四个视角均出现末包比前一包短 1 tick（1 µs），恰好对应全部 4 个 `avg_frame_rate` 与 `r_frame_rate` 不同的文件。[格式与包时钟](c_full_audit/video_format.csv)
- **偏差如何累积。** Demo 的 43,916 个视角行全部可由 `float32(frame_index) / float32(fps)` 复现，微秒级偏差与该浮点运算和有理数 PTS 的精度相符。CSV 两组的 PTS 步长固定，而源时间戳的相邻差可在邻近纳秒值间变化。对每个文件连接 Δ 的首末两点，Pro 和 Standard 的逐行 Δ 偏离这条直线最多分别为 0.933 和 0.668 µs。Standard 有 46 个文件用 33.333 ms 的固定展示步长，另 2 个为 25 fps。超 1 ms 的 12,820 行分布于 Standard 的 12 个文件。所有来源中，超过各自半个标称帧周期的共有 **0 / 178,512 行**。上述偏差符合近似线性的时钟累积差，均未伴随行数或 PTS 步长异常。[时钟统计](c_full_audit/video_clock.csv)
- **缺行与间隔。** 178,328 对视频相邻 PTS 的间隔为 33.319–40.000 ms，按视角展开的 178,328 对轨迹相邻时间间隔为 33.318–40.000916 ms。旁车的 134,492 个相邻间隔为 33.318–40.000001 ms。三类时间轴上的非正间隔和超过 50 ms 的间隔均为 0。旁车的 `_message_index` 全部从 0 按行递增，`frame_id` 均对应文件相机名。相对于轨迹，旁车时间键缺失、多余和同一行时间戳不等的计数均为 0。Demo 直接比较共享轨迹行，其数据格式没有独立的相机时间 CSV。[时钟统计](c_full_audit/video_clock.csv)
- **跨视角。** 逐记录以头左为参照，将其余相机的整数 PTS 化为共同有理数刻度后逐行核对。头右 66,070 对、左腕和右腕各 23,186 对，共 **112,442 对**相对 PTS 全部精确相等，两侧均无多余行。由此可按同一输出行号对应多视角与轨迹。相机传感器的实际曝光时差仍需硬件时间或独立光学参照才能量化。[时钟统计](c_full_audit/video_clock.csv)

## 逐帧灰度检查

每个原生帧经 FFmpeg 面积缩放到 64 × 48，输出全范围 8 位灰度。亮度为 3,072 个像素的均值。相邻变化为同文件相邻两帧对应像素绝对差的均值（MAD，单位为灰度级）。每路视频的第一帧只计亮度。帧内**所有灰度值 ≤ 5** 计为技术黑帧，**相邻两帧的 3,072 个对应像素全部相等**计为降采样重复。全量分别为 **0 / 178,512 帧**和 **0 / 178,328 对**。这些指标只描述导出画面的明暗和变化，不能量化手部遮挡、真实运动速度或补货成败。[逐来源与视角的灰度统计](c_full_audit/video_image.csv)

## 复现与使用边界

在仓库根目录运行。原始输入只读，本次环境为 Python 3.13.9、NumPy 2.4.0、pandas 2.3.3、PyArrow 23.0.1、FFmpeg / ffprobe 4.4.2，另需 GNU `timeout`。全量使用 5 个 worker，每路解码、滤镜及输出编码各限制 1 线程，每批最多 32 个灰度帧。单文件包探测限时 90 秒，完整解码限时 300 秒。脚本逐批归约灰度数据，临时日志用于核对每个解码帧的 PTS 和原生格式。[核查脚本](../experiments/c_full_video_decode.py)

```bash
PY=/mnt/disk/zhoutianyu/miniconda3/bin/python
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
# 全量重新解码、复核并生成四张公开聚合表。为保留已有结果，每次全解码使用新的子目录。
"$PY" -B experiments/c_full_video_decode.py --workers 5 --run-dir runs/c_full_video/reproduction
# 使用本次完成的私有帧统计，再核对所有原始包并对代表文件进行第二次解码。
"$PY" -B experiments/c_full_video_decode.py --run-dir runs/c_full_video/full --verify-only
# 只从本次完整解码与复核台账重算聚合表。
"$PY" -B experiments/c_full_video_decode.py --run-dir runs/c_full_video/full --summarize-only
for f in runs/c_full_video/full/aggregates/video_*.csv; do cmp "$f" "research/c_full_audit/$(basename "$f")" || exit 1; done
```

全量 ffmpeg 以 `-xerror -err_detect explode` 运行，184/184 文件成功退出，解码日志中警告与错误均为 0。复核时重读了 184 个输入的流清单、全部包时钟和已保存的逐帧数值，并另用 `ffprobe -show_frames` 对 **6 路、6,260 帧**作第二次完整解码。这 6 路覆盖现有的各来源与头/腕组合、最大绝对时差，以及平均/标称帧率相异的情况。两次解码入口均属 FFmpeg，第二次逐帧返回的 PTS、最佳估计时间戳、原生尺寸和像素格式与首轮一致。[核查脚本](../experiments/c_full_video_decode.py)

公开 CSV 中 `scope` 指定聚合维度，`overall`、`dataset`、`split`、`view`、`dataset_view` 是同一批帧的不同分组。逐文件与逐帧时间、数值统计只保存在受限并由 Git 忽略的 `runs/c_full_video/`。本核查使用所有 split 进行离线附件核验，未以视频或验证、测试输出拟合策略。上述完整性覆盖已交付的导出文件，各通道在导出前同步漏采的事件仍无法从这些文件识别。[覆盖清单](c_full_audit/video_coverage.csv) · [时钟](c_full_audit/video_clock.csv) · [格式](c_full_audit/video_format.csv) · [灰度](c_full_audit/video_image.csv)
