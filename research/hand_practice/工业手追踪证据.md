# 工业手追踪的字段、质量与手势证据

**2026-11-21 复核。** 证据来自四组数据格式、追踪接口或交互实现的一手文档与固定源码。产线装配识别效果需要另行验证。

## 1. Lightwheel 的手部坐标与质量通道

- **MCAP 原始 Protobuf** 的 `/pose/left_hand`、`/pose/right_hand` 各有 21 个 `Transform`。手部位置用右手世界坐标，X 向前、Y 向左、Z 向上，单位为米。四元数按 `w, x, y, z` 定义，赛题 Pro/Standard CSV 的腕姿读取代码按 `transforms[0].quat.w/x/y/z` 字段名取值。0 为腕，5/9/13/17 为四根非拇指 MCP。[MCAP Hand Pose v1.0.0](https://docs.lightwheel.net/egocentric_data/v1.0.0/mcap_data/pose/hand#coordinate-frame) · [当前 Hand Pose v1.0.1](https://docs.lightwheel.net/egocentric_data/mcap_data/pose/hand#coordinate-frame) · [本地腕姿读取代码](../../experiments/c_feas_hand_channels.py#L34)
- **LeRobot v3.0 Parquet** 的 `observation.state.hand_{left,right}_world` 和对应的 `_world_rotation` 也明确采用世界坐标、米和 `qw, qx, qy, qz`。该格式页未明示轴向，不能由 MCAP 手部页确认 LeRobot 的轴向。两份关节表对拇指 1–3 号的命名有差异。本题 Pro/Standard CSV 与 Demo Parquet 的字段和关节含义分别核对。[LeRobot Parquet 字段及关节表 v1.0.0](https://docs.lightwheel.net/egocentric_data/v1.0.0/lerobot_data/format_specification#data-parquet-schema) · [本地关节映射与无量纲误差核验](../C题关节映射与无量纲误差核验.md)
- MCAP 的 `Transform` 只含位置和旋转。DevKit 将 `/annotation/bad_frame/pose/hand`（`annotation.BadFrameHand`）列为可选的逐帧手部质量通道。所核来源未确认坏帧枚举及判定阈值、逐关节置信概率或协方差，也未披露遮挡补全算法。质量消息缺失时，手点可见性及精度仍待核验。赛题的参考合格标记与在线可用信息应分别记录。[DevKit 固定提交 §3.1](https://github.com/LightwheelAI/LW-Egosuite-DevKit/blob/ef23daaf2327fb35b66420dac443319046163559/README.md#L129-L135)

## 2. Ultraleap LeapC 的手型估计与追踪字段

- `grab_strength` 是 0–1 的抓握手型估计，对应四根非拇指向掌心弯曲。`pinch_strength` 是 0–1 的捏合手型估计，对应拇指与任一同手其他手指。`grab_angle` 是手指相对掌的平均角（rad）。握力、手物接触和抓取成功各需独立参照。[LeapC `LEAP_HAND`](https://docs.ultraleap.com/api-reference/tracking-api/struct/struct_l_e_a_p___h_a_n_d.html)
- 原生 `pinch_distance` 字段只写拇指与食指之间的距离（mm）。Unity 的 `Hand.PinchDistance` 文档进一步写明拇指与食指各取末两节指骨，在两组骨段间取最短距离。固定版本的 `CopyFromLeapC` 路径将原生值从毫米换成米后直接赋值，支持这一距离口径。原生追踪服务的距离实现细节仍未核实。[7.3.0 随附 LeapC 头文件](https://github.com/ultraleap/UnityPlugin/blob/833d82e7333a5f37ebc0844d02431acf74f35d24/Packages/Tracking/Core/Runtime/Plugins/Android/Other/arm64-v8a/LeapC.h#L1689-L1711) · [Unity `Hand.PinchDistance`](https://docs.ultraleap.com/api-reference/unity-api/class/class_leap_1_1_hand.html#var-Leap.Hand.PinchDistance) · [7.3.0 复制及换算源码](https://github.com/ultraleap/UnityPlugin/blob/833d82e7333a5f37ebc0844d02431acf74f35d24/Packages/Tracking/Core/Runtime/Plugins/LeapCSharp/CopyFromLeapCExtensions.cs#L70-L79)
- `confidence` 官方注明 **“Not currently used (always 1.0)”**，`flags` 保留未用。`visible_time` 是这只手累计被追踪的时长（μs）。失追后重获会分配新 ID。`LEAP_DIGIT.is_extended` 表示手指大致伸直，结构中没有逐指可见性字段。[`LEAP_HAND`](https://docs.ultraleap.com/api-reference/tracking-api/struct/struct_l_e_a_p___h_a_n_d.html) · [`LEAP_DIGIT.is_extended`](https://docs.ultraleap.com/api-reference/tracking-api/struct/struct_l_e_a_p___d_i_g_i_t.html#_CPPv4N10LEAP_DIGIT11is_extendedE)
- 服务用双目图像拟合手模型，遮挡和出视野部分依据可见部分、历史及模型约束估计。逐帧追踪值及 `confidence=1` 无法确认真实可见性。所核文档未给出两个 strength 的精确公式、误差校准或统一离散阈值。按指定时间取帧时，可在已存帧间插值，晚于最新帧则外推，过远可能抖动。文档只说明保留少数历史帧，未给固定秒数。本题回执应区分源时间、到达时间与插值或预测的目标时间。[Leap Concepts 的 Frame 与 Frame Interpolation](https://docs.ultraleap.com/api-reference/tracking-api/leapc-guide/leap-concepts.html#frame)

## 3. Khronos OpenXR 的有效位、追踪位与活动状态

- `xrLocateHandJointsEXT` 在指定的 `baseSpace` 和 `time` 下定位关节。默认关节集有 26 个关节，返回位置、朝向、半径及 `locationFlags`，可另取速度。位置有效位未置时，半径也未定义。[默认关节数 `xr.xml`](https://github.com/KhronosGroup/OpenXR-Docs/blob/18ebc0374da23c020ef4c949f9b144ffae6160ef/specification/registry/xr.xml#L275-L276) · [查询坐标与时间](https://github.com/KhronosGroup/OpenXR-Docs/blob/18ebc0374da23c020ef4c949f9b144ffae6160ef/specification/sources/chapters/extensions/ext/ext_hand_tracking.adoc#L185-L225) · [输出字段](https://github.com/KhronosGroup/OpenXR-Docs/blob/18ebc0374da23c020ef4c949f9b144ffae6160ef/specification/sources/chapters/extensions/ext/ext_hand_tracking.adoc#L289-L329)
- `isActive=true` 时，规范要求每个关节的 `POSITION_VALID` 和 `ORIENTATION_VALID` 均置位，任一分量的 `TRACKED` 位仍可未置。`isActive=false` 表示未检出手部输入或应用失去输入焦点，此时所有关节的两个 `VALID` 位都必须清除。通用位定义允许推断或最后已知的位置仍有效，并要求应用仅读取有效分量。是否被相机直接看见需由独立信息核验。[扩展的活动状态条文](https://github.com/KhronosGroup/OpenXR-Docs/blob/18ebc0374da23c020ef4c949f9b144ffae6160ef/specification/sources/chapters/extensions/ext/ext_hand_tracking.adoc#L273-L284) · [通用 `XrSpaceLocationFlagBits` 定义](https://github.com/KhronosGroup/OpenXR-Docs/blob/18ebc0374da23c020ef4c949f9b144ffae6160ef/specification/sources/chapters/spaces.adoc#L822-L858)
- 基础扩展要求关节输出表征无阻碍的手部活动范围。持控制器妨碍动作或系统追踪手指的能力受限时，规范要求利用已有信息模拟无阻碍的活动范围。输出呈闭拳可以是这种模拟的结果，判定手指碰掌或手物接触仍需独立观测。该扩展未规定 grab/pinch 分类器、遮挡处理算法或动态识别窗长。[无阻碍手部活动范围条文](https://github.com/KhronosGroup/OpenXR-Docs/blob/18ebc0374da23c020ef4c949f9b144ffae6160ef/specification/sources/chapters/extensions/ext/ext_hand_tracking.adoc#L248-L261)

## 4. MRTK3 的捏合归一化与布尔判定

- 固定提交的 `d` 为拇指尖与食指尖的欧氏距除以食指三段长之和。分母依次取近端关节至中间关节、中间至远端、远端至指尖。指长取得后缓存。指长例程每次先查询食指尖，失败即清空缓存，后续取得关节点数据时重算。微软概念页仍写绝对世界距离并称将来才按手大小归一化。上述算法以该提交为准。[固定源码指长例程](https://github.com/MixedRealityToolkit/MixedRealityToolkit-Unity/blob/83c8c1d5dd26cb80dd2dd6eaa910ddc326ea070f/org.mixedrealitytoolkit.input/Subsystems/HandsAggregator/MRTKHandsAggregatorSubsystem.cs#L149-L198) · [微软 Pinch characteristics](https://learn.microsoft.com/en-us/windows/mixed-reality/mrtk-unity/mrtk3-input/packages/input/hand-tracking#pinch-characteristics)
- `pinchAmount = 1 − InverseLerp(closed, open, d)`。`closed` 和 `open` 是连续量取 1 与 0 的端点，重置值和同提交的默认配置均为 **`closed=0.25`、`open=0.75`**。函数只用 `d < open` 判定 `isPinching`，所以 `closed < d < open` 时 `isPinching` 已为真，连续量仍小于 1。这里的两端点没有组成双阈值迟滞，函数也没有驻留时间或动作分段判定。[固定源码 `TryGetPinchProgress`](https://github.com/MixedRealityToolkit/MixedRealityToolkit-Unity/blob/83c8c1d5dd26cb80dd2dd6eaa910ddc326ea070f/org.mixedrealitytoolkit.input/Subsystems/HandsAggregator/MRTKHandsAggregatorSubsystem.cs#L277-L318) · [`Config.Reset`](https://github.com/MixedRealityToolkit/MixedRealityToolkit-Unity/blob/83c8c1d5dd26cb80dd2dd6eaa910ddc326ea070f/org.mixedrealitytoolkit.input/Subsystems/HandsAggregator/MRTKHandsAggregatorConfig.cs#L75-L84) · [同提交的默认配置资产](https://github.com/MixedRealityToolkit/MixedRealityToolkit-Unity/blob/83c8c1d5dd26cb80dd2dd6eaa910ddc326ea070f/org.mixedrealitytoolkit.input/Assets/Default%20Configs/MRTKHandsAggregatorConfig.asset#L15-L18)
- 函数返回值表示本次所需关节数据和指长是否取到。取数失败时两个手势布尔输出置 `false`，`pinchAmount` 置 0，解释输出前应先检查返回值。取数成功后，`isReadyToPinch` 由视野角与掌面朝向共同判定，独立于 `isPinching`。这几个量用于交互手势，赛题是否真实接触工件需另取证。[固定源码 `TryGetPinchProgress`](https://github.com/MixedRealityToolkit/MixedRealityToolkit-Unity/blob/83c8c1d5dd26cb80dd2dd6eaa910ddc326ea070f/org.mixedrealitytoolkit.input/Subsystems/HandsAggregator/MRTKHandsAggregatorSubsystem.cs#L277-L318)

本题可分别评价位置、旋转、连续指形和双手相对量。手势判定应同时记录数据是否可用、是否经过推断。闭拳属于手型标签，可按手用关节几何和清楚画面复核。抓取与接触涉及物体，应另标对象及可见交互。接触时刻被挡时可记可判前后态所夹的时间范围，或记为未知。评价离散手势和动作起止时，还需定义本地标签、持续时间和误差参照。[本题视频复标办法，第 5 节](../C题手部轨迹的学术与工业处理实践.md)
