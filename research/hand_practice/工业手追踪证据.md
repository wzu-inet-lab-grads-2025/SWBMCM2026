# 工业手追踪证据：字段、质量与手势的边界

**核对日期：2026-11-21。** 以下选四组一手官方文档/项目源码；是可借鉴的商用追踪与交互实践，**不是产线装配识别效果证明**。“未披露”仅指所核来源没有说明，不断言厂商内部没有实现。

## 1. Lightwheel：骨架坐标与质量注释是不同数据

**来源与可核位置：** [Hand Pose v1.0.1](https://docs.lightwheel.net/egocentric_data/mcap_data/pose/hand#coordinate-frame)，查 *Coordinate Frame / Topic & Message Type / Joint Index and Conventions*；[官方 DevKit 固定提交 README §3.1](https://github.com/LightwheelAI/LW-Egosuite-DevKit/blob/ef23daaf2327fb35b66420dac443319046163559/README.md#31-source-topics-raw-mcap)。

- 每手 **21 关节**，世界系右手坐标，X 前、Y 左、Z 上；位置为**米**，四元数顺序 **wxyz**。0 为腕，5/9/13/17 为四根非拇指 MCP。不是相机像素，也不能将另一 SDK 的关节编号原样套入。
- DevKit 将 `/annotation/bad_frame/pose/hand` 明列为**可选逐帧手部质量通道**；手部 `Transform` 定义本身只有位置、四元数。所核页面未给逐关节置信概率、协方差、坏帧判定阈值或遮挡补全算法；不能把“有坐标”“没有质量消息”解释成“真实可见且准确”，也不能凭主题名推断具体坏帧枚举。
- **对本题：**位置、腕旋转、指弯可由明确字段分别定义；参考合格标记与在线可见信息必须分开，发布方格式说明不能替代本地导出及精度核验。

## 2. Ultraleap LeapC：连续手型分数不是握力，也不是可见性

**来源与可核位置：** [LEAP_HAND / LEAP_DIGIT 的 Public Members](https://docs.ultraleap.com/api-reference/tracking-api/group/group___structs.html)；[Leap Concepts](https://docs.ultraleap.com/api-reference/tracking-api/leapc-guide/leap-concepts.html)，查 *Coordinate System / Frame / Frame Interpolation / Clock Rebasing*。

- `grab_strength` 为 **0–1 抓握手型估计**：四根非拇指向掌心弯曲；`pinch_strength` 为 **0–1 捏合手型估计**：拇指可与任一其他手指捏合。它们不是牛顿单位的力、接触证据或成功抓住物体的概率。`pinch_distance` 则只描述**食指与拇指**距离；`grab_angle` 为手指相对掌的平均角。LeapC 原生单位是 **mm、μs、rad**，不能混用 Unity 包装层单位或本题的米/度。
- 关键限制：`confidence` 官方明确 **“Not currently used (always 1.0)”**；`flags` **保留未用**；`visible_time` 是已追踪时长（μs），不是本帧可见比例。丢失后重获手会分配新 ID。`LEAP_DIGIT.is_extended` 表示手指大致伸直，**不是可见/遮挡标志**；该结构未提供逐指可见性置信字段。
- 官方说明：双目图像拟合内部手模型，遮挡/出视野部分会依据可见部分、历史及模型约束**估计**。所核文档不披露 strength 精确公式、校准误差、内部历史长度或统一离散手势阈值。插值按所求时间合成；晚于最新帧则外推，过远可能抖动；历史仅保留“少数帧”，未承诺固定秒数。
- **对本题：**可借鉴“连续形状量＋独立状态标志”，不能借 `confidence=1` 做可信度门控；回执还必须区分源时间、到达时间与插值/预测时间。

## 3. Khronos OpenXR：有效、追踪中、物理可见不是同义词

**来源与可核位置：** [XR_EXT_hand_tracking 固定规范源码](https://github.com/KhronosGroup/OpenXR-Docs/blob/18ebc0374da23c020ef4c949f9b144ffae6160ef/specification/sources/chapters/extensions/ext/ext_hand_tracking.adoc)，查 *Locate hand joints / XrHandJointLocationsEXT / Conventions of hand joints*；[通用空间有效/追踪语义](https://github.com/KhronosGroup/OpenXR-Docs/blob/18ebc0374da23c020ef4c949f9b144ffae6160ef/specification/sources/chapters/spaces.adoc#L708-L724)。

- 默认 **26 关节**；`xrLocateHandJointsEXT` 按指定 **baseSpace 和 time** 返回 pose、半径及 `locationFlags`，可另取速度。`isActive=true` 要求所有关节位置/朝向 **VALID**，但部分可以不 **TRACKED**；推断/最后已知值可能仍有效。`isActive=false` 还可能是**应用失去输入焦点**，不能直接归因为遮挡。上述是位标志，不是连续置信概率或逐像素可见性。
- 尤其注意：基础扩展要求表现**空手无阻碍的运动范围**，持控制器或手指追踪受限时可能模拟无阻碍手型；不能拿返回“握拳”直接证明真实手指已碰掌或已接触工件。该扩展不规定 grab/pinch 分类器、底层遮挡算法或统一动态识别窗长。
- **对本题：**输出坐标之外需保存其有效性、追踪状态和来源；OpenXR 的标志也不能未经验证映射成赛题质量标签。

## 4. MRTK3：公开可复核的“几何 → 连续量 → 布尔判定”

**来源与可核位置：** [微软 Hand tracking 的 Pinch characteristics](https://learn.microsoft.com/en-us/windows/mixed-reality/mrtk-unity/mrtk3-input/packages/input/hand-tracking#pinch-characteristics)；[项目固定源码 TryGetPinchProgress](https://github.com/MixedRealityToolkit/MixedRealityToolkit-Unity/blob/83c8c1d5dd26cb80dd2dd6eaa910ddc326ea070f/org.mixedrealitytoolkit.input/Subsystems/HandsAggregator/MRTKHandsAggregatorSubsystem.cs#L277-L318)及 [Config.Reset](https://github.com/MixedRealityToolkit/MixedRealityToolkit-Unity/blob/83c8c1d5dd26cb80dd2dd6eaa910ddc326ea070f/org.mixedrealitytoolkit.input/Subsystems/HandsAggregator/MRTKHandsAggregatorConfig.cs#L75-L84)。

- 固定实现取 `d=拇食指尖距离/食指骨段总长`；`pinchAmount=1−InverseLerp(closed,open,d)`。配置重置值 closed=**0.25**、open=**0.75**，是此实现的归一化默认值，不是行业通用阈值。`isPinching` 实际判定 **d<open**，不等于 `pinchAmount=1`；另有由手部朝向、视野位置决定的 `isReadyToPinch`。查询返回 bool 表示数据取得成功，不能与手势 bool 混淆。
- **版本差异不能略去：**微软概念页仍写绝对世界距离、将来才归一化；上述固定源码已经按指长归一化，以源码描述该版本，不把两者拼成同一算法。指长首次取得后缓存，失追再取得时重算；该函数没有多帧驻留或动态动作分段，也没有双阈值状态迟滞，open/closed 在此主要是连续量映射端点。不能据此声称整个 MRTK 或底层追踪无时域处理。

**落到本题：**最有帮助的是分别评价位置、旋转、连续指形、双手相对量，并将“数据不可用/推断中”与“未握拳/未捏合”区分。离散握拳、抓取或装配阶段需另外定义标签、持续时长/迟滞和独立参照；这里没有可核的真实产线装配分段方法与验证数据，故不补写案例或准确率。以上来源不提供本题回访通道报价，也不替队员决定正式状态。
