# C 题逐帧图文一致性复核

冻结的 OpenAI CLIP ViT-B/32 已逐帧编码 **69 条记录、184 个 MP4、178,512 个视角帧**。在可与同记录异文比较的 335 段中，官方英文描述 **97/335 段排第一（28.96%）**，均匀猜测为 24.37%，保持本记录文本频数的置换基线为 21.94%。与预定的下一条异文一对一比较，原配描述在 **195/335 段（58.21%）**胜出。逐帧画面提供了与动作文字相关的信息，但只凭这组特征进行同记录动作检索，多数区间仍无法把原配排到第一。[分组检索与对照](c_dense_audit/text_retrieval.csv)

## 核查问题与分母

同一段画面中，冻结图文模型给官方英文动作描述的分数，是否高于给同一记录其他动作描述的分数？每个视角、每个展示帧独立计算一次视觉表征。段内计分使用半开区间中的全部帧。相机数、帧数、区间数和记录数分别计数，长视频及多相机记录在不同口径中的权重由此可查。

69 条记录共有 349 个原始区间，全部纳入附件质检，包括官方长度池剔除的短段。按同记录内的 CLIP 词元序列去重，共有 282 个「记录、异文」组合。一个候选即使在同记录出现多次，也只占一个检索名额。

| 文本可区分的范围 | 区间数 | 能回答的问题 |
|---|---:|---|
| 有同记录异文，且本段文本在此记录仅出现一次 | 263 | 该段唯一文字能否排在其他候选之前 |
| 有同记录异文，本段文本在此记录重复 | 72 | 能否排在异文前。同文的多次执行共享同一个文本向量 |
| 整条记录仅有一个文本候选 | 14 | 3 条记录可算原配余弦，同记录内缺少错配对照 |

前两行共 66 条记录、335 段。这里的可区分性指文字输入有差异。不同措辞可能指同一动作，某一视角也可能看不到文字提及的物体。区间均值还会丢失先后顺序，即使逐帧特征正确，拿起和放回同一物体仍可能得分接近。因此低分或错配胜出只能说明这次比较缺少区分力，模型排序无法裁定标注对错。

原始源时钟共有 66,070 个记录内时刻，65,765 个落在标注半开区间内。按各记录实际相机数展开，区间内有 177,692 个视角帧，区间外有 305 个时刻、820 个视角帧。区间外的向量保留在缓存，计分分母只含可对齐的时刻。

## 同一记录内，画面能把动作文字区分到什么程度

下表按段计数，每一段内对全部时刻及现有相机等权。每段平均有 4.92 个候选。第三个比较同时使用两段画面，检验两段各配原文的总得分能否超过互换文字后的总得分。来源行和划分行是同一批数据的两种拆分，九个来源与划分交叉组见 CSV。[完整分组结果](c_dense_audit/text_retrieval.csv)

| 范围 | 有异文记录 / 段 | 原配排第一 | 同记录标签置换期望 | 原配胜过预定异文 | 两段原配胜过交换 |
|---|---:|---:|---:|---:|---:|
| 全部 | 66 / 335 | 97/335（28.96%） | 21.94% | 195/335（58.21%） | 243/335（72.54%） |
| EgoDemo | 31 / 118 | 34/118（28.81%） | 27.12% | 59/118 | 78/118 |
| EgoPro | 13 / 63 | 17/63（26.98%） | 20.63% | 34/63 | 47/63 |
| EgoStandard | 22 / 154 | 46/154（29.87%） | 18.50% | 102/154 | 118/154 |
| 训练 | 52 / 238 | 68/238（28.57%） | 23.06% | 132/238 | 169/238 |
| 验证 | 7 / 35 | 9/35（25.71%） | 20.00% | 22/35 | 25/35 |
| 测试，仅质检 | 7 / 62 | 20/62（32.26%） | 18.72% | 41/62 | 49/62 |

- **每帧与整段。** 335 段覆盖 62,675 个可对照的多视角时刻。直接逐时刻排序，原配取得 22,493 个第一名积分（35.89%），逐时刻均匀基线为 23.97%。与预定异文比较，原配在 38,861/62,675 个时刻（62.00%）得分更高。逐段汇总则给每段一次权重，原配、错配的段均余弦分别为 0.269637、0.265535，差为 **+0.004102**。逐记录等权时，原配排第一的段占比均值为 33.07%。
- **文本仅出现一次的子集。** 在本段文字可定位到同记录内唯一一次标注的 263 段中，原配 **82/263（31.18%）**排第一，均匀基线为 23.77%，原配 146/263 次胜过预定异文。另有 9 条记录贡献 72 个有异文但本段文字重复的区间，其原配 15/72 排第一。剩余 3 条记录的 14 段均只有一种措辞，没有可报告的同记录命中率。[分母](c_dense_audit/text_coverage.csv)
- **两个区间交换文字。** 335 个有向配对经去重对应 330 个无向段对。按预定有向口径计，243 次原配总分较高，92 次交换后较高，平分 0 次，平均每段原配优势为 **+0.003935**。EgoDemo 单段原配对下一异文恰为 59 胜、59 负，两段交换对照为 78/118 原配胜出。部分文字能在同一记录多段中普遍得高分，是否引入另一段画面会改变所回答的问题。
- **动词方向对照。** 六条记录提供 30 对符合固定词表的取／放、开／关方向对照。原配胜过预定异文 **26/30**，两段交换比较 **30/30**，但原配在全部同记录候选中只排第一 **11/30**。这组数字只描述此文本规则覆盖的 30 对，不能外推到全部 349 段。
- **视角分母。** 头左、头右单独计分时，原配分别 96/335、104/335 排第一。左腕、右腕各有 97 段可对照，对应 26/97、33/97。腕部视频只存在于部分记录，跨视角百分比还受相机装配与来源构成影响。[分视角结果](c_dense_audit/text_retrieval.csv)

## 模型、时间与计分

1. 固定公开的 OpenAI CLIP ViT-B/32 图像塔和文本塔。模型仓库版本为 `3d74acf9a28c67741b2f4f2ea7635f0aaf6f0268`，权重 SHA-256 为 `a63082132ba4f97a80bea76823f544493bffa8082296d62d71581a4feff1576f`。脚本同时核查配置、词表和分词器的 Git 对象摘要。从本地只读模型目录加载，两塔均为评估模式，梯度关闭。英文描述用原文，未添加提示词，最长输入为 25 个词元，均低于模型的 77 词元上限。[固定版本及模型卡](https://huggingface.co/openai/clip-vit-base-patch32/tree/3d74acf9a28c67741b2f4f2ea7635f0aaf6f0268)
2. FFmpeg 保留展示顺序和整数 PTS，全文件从头解码。短边按 bicubic 缩放为 224，长边等比取整，转 RGB24 并居中裁出 224 × 224，按模型配置的 RGB 均值、标准差归一化。此处使用 FFmpeg 的缩放实现。实跑的图像塔用 GPU FP16 推理，文本塔用 CPU FP32 推理。逐帧投影为 512 维，在 FP32 中作 L2 归一化，以 FP16 保存。图像编码只接收像素，每个未落入区间的帧也有向量。每个文件核对原视频 SHA-256、实际输出行数、容器声明帧数、源时刻行数、原生分辨率，以及解码 PTS 与全部视频包排序后 PTS 的逐项相等性。[脚本](../experiments/c_dense_text_frames.py)
3. 将原始区间的英文、起止秒和序号与官方索引逐项核对。Demo 直接使用 Parquet 中实际存储的 float32 时间值，Pro、Standard 用逐相机时间旁车与轨迹的整数纳秒行键对齐，按首条语义消息反推记录零点。将源时刻与十进制端点作为有理数比较，采用 `[开始, 结束)`。多相机融合前核对各相机的展示时间在换算至共同刻度后相等。[源时钟与端点依据](C题全记录轨迹与语义核查.md)
4. 重新归一化已保存的图像向量，与本记录全部不同描述的单位文本向量逐帧计算余弦。主结果在同一源时刻对现有视角等权取均值，再在区间内对实际时刻等权取均值。每段取余弦最高的候选，平分并列第一的名额。均匀猜测基线按本段候选数 `K` 取 `1/K` 再按相同分母平均。另对全部有异文的区间，保持模型排名和本记录各文本出现次数，计算在区间间随机交换标签后的第一名命中率期望。它等于对每段并列第一候选的记录内出现频率取平均，再对区间取平均，无须抽样。CSV 另给每个相机的结果，以及按帧和按记录等权的口径。左右腕相机仅覆盖有腕部视频的记录。
5. 固定错配按时间顺序选下一条词元不同的描述，抵达末段后循环。每段的候选由文字与顺序确定，同一段所有帧共用这一对照。`mean_gap` 为原配减错配的段均余弦差。`swap_mean_gap` 同时使用两段的画面，计算两次原配均分减去交换文字后的两次均分，可抵消某句话在两段中普遍得分偏高。每段产生一个有向配对，两段有时会互选；这些配对共享记录和画面。胜率对相等分数计半分。
6. 另列按固定词表可识别出相对动作方向的有向配对。只接受开头动词属于取／放或开／关两组中的一类，且本句不含其他预定义组的词。预定下一异文须落在对应另一类。这个文字规则筛出 30 对，不涉及图像分数。完整词形见脚本。它可作窄范围检查，无法判断一张静态图是否拍到了动作方向。

三种来源与三个官方划分均独立列数，记录间不交换候选，也不拟合任何参数、提示词或阈值。测试划分只参加附件质检。连续帧及同一动作的多个视角存在相关性，本报告使用描述性比例。

整套评分代码与官方索引摘要在全量计分前锁定。此次 `score_protocol.json` 的 SHA-256 为 `058b5e75d869ae8c8385bab117fd290540e4abb3ebb65ecf3ec478066fbb4d96`，复算时脚本会核查代码、索引和协议一致。

184/184 个文件均通过解码帧数、容器帧数、源行数与 PTS 检查。另与此前独立解码留存的整数 PTS 逐行比对，**178,512/178,512 个一致**。实跑使用一张共享 RTX 4090，PyTorch 峰值预留显存为 230 MiB，运行中一次驱动进程用量读数为 714 MiB。[此前逐文件解码协议](C题全视频解码与时钟核查.md)

另用训练集首条 Demo 记录的四个视角，对固定展示帧号 0、7、8 作数值复验，共 12 帧，覆盖第一批与第二批的交界。在 CPU 上调用模型公开的图像特征接口并逐帧对照缓存。相同 FFmpeg 缩放输入下，缓存向量与 FP32 复算向量的余弦最小值为 0.999996，中位数为 0.999998。改用原生 RGB 和官方 PIL 预处理器后，余弦最小值为 0.981510，中位数为 0.993960。因此报告数值对应所记录的 FFmpeg 缩放实现，不能假设换用 PIL 后每个候选的名次都相同。

## 本地复算

在仓库根目录运行。`PY` 指向已有的 Python 3.11 环境，实跑用 PyTorch 2.9.1、Transformers 4.57.3 和 FFmpeg 4.4.2。`fetch` 只下载并验证上述公开模型，后两步离线。`encode` 默认用两个 CPU 推理线程，传入 `--gpu-uuid` 可指定一张经确认有空余的卡。初始批量为 8，PyTorch 分配器上限 896 MiB，出现显存不足会减批并可回退 CPU。间隔检查发现卡空余低于 3 GiB 时转 CPU。报告的分配器峰值限于 PyTorch 预留的显存，驱动上下文另有开销。

```sh
"$PY" experiments/c_dense_text_frames.py fetch
"$PY" experiments/c_dense_text_frames.py lock
"$PY" experiments/c_dense_text_frames.py encode
"$PY" experiments/c_dense_text_frames.py score
"$PY" experiments/c_dense_text_frames.py verify
```

`runs/c_dense_vlm/` 内的模型、协议、逐文件 PTS 与向量、逐段对照均留在本机。再次运行 `encode` 会核验已有完整文件，从下一个缺失文件继续。公开表只给分组分母和对照统计。[覆盖与区间分母](c_dense_audit/text_coverage.csv) · [同记录检索与错配对照](c_dense_audit/text_retrieval.csv)
