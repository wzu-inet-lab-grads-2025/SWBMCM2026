# C 题迭代架构草案

建议正式代码按 `src/q1/`、`src/q2/`、`src/q3/` 组织。队伍仍在讨论代表点、尺度和目标，原型继续放在 `experiments/`。可先固定官方环境划分、信息可见规则和结果分母，让候选方法在同一协议下互换。以下接口是讨论草案。[决策依赖图](C题决策依赖图.md)

## 按变化原因划分职责

| 职责和建议位置 | 输入与输出 | 现有入口或待比较方法 |
|---|---|---|
| 记录索引与来源适配，`shared/data` | 输入附件版本和官方 split，输出同一记录的时间、手别、关节数组、标签及来源。离线保留记录键、环境和排除原因。 | Q1、Q2 探索已共用[官方索引入口](../experiments/c_records.py)。Q3 另按作业族和协议从本 split 抽片段。 |
| 状态与质量，`q1` | `state(observations)` 计算代表点或双手相对量，附单位、可用标记和成立条件。质量保留数值有效性、原始标记及标记是否已知。 | 腕点、掌部代表点和相对量均可作为版本。事件统计可选择起点、持续或恢复。[质量事件入口](../experiments/c_q1_quality_transitions.py) |
| 预测和请求，`q2` | `predict(visible_history, now)` 输出估计及适用的误差范围。`request(view)` 读当前可见观测、在途请求和剩余预算，输出请求或等待。回放器负责披露，评分器单独持有被遮挡参考。 | 预测器、请求规则分别替换。已有[固定请求回放](../experiments/c_q2_diagnostic.py)和[常速度训练探针](../experiments/c_q2_velocity_probe.py)。 |
| 时长与调度，`q3` | 时长估计只接收已公开的作业条件和已返回前缀。固定决策时点，策略通过 `policy(view)` 返回作业、预留、复核、等待或停止。 | 已有 `run_trial(trial, policy)`。在同一策略中可以固定排序与等待，仅替换预留函数。动作准入、时间推进和结算由[引擎](../experiments/q3_replay/engine.py)统一执行。 |
| 评估、试验记录和验收，`checks/`、`runs/` | 在记录或环境层面汇总 Q1/Q2，按案例和种子配对汇总 Q3。一次比较保存数据与协议版本、代码提交、方法参数、独立样本分母及聚合指标。 | 对齐既有合成回放、手算与未来信息扰动检查。实验用数据只在本地留详细记录。[验收清单](C题验收清单.md) |

## 改一个方法，需要重跑什么

| 具体改动 | 可以复用 | 重新生成和核对 |
|---|---|---|
| 在相同腕点上比较保持末值与常速度 | 官方 split、状态、参考池、计时、分箱和评分权重 | 在同一批记录和窗上生成两组预测及配对差。单列历史不足时退回基线的次数。 |
| 用掌部中心代替腕点，或改用无量纲距离 | 原始记录、官方 split、时间对齐 | 生成新状态或尺度版本，重数合格点和窗。报告各自全池及交集上的效果。只有分母和量纲可比时才解读误差差值。 |
| 固定排序，换第二种预留 | 同种子作业分配、排序和等待、时间费用规程、评分器 | 按新预留重新回放，独立复算账本，比较按时率、拖期、费用及占用变化。 |

组装一次试验只需要一个入口接收协议配置和方法。配置记录 `split`、状态与尺度、参考规则、可见信息、资源约定、方法参数和汇总权重。训练所得变换随模型保存，验证使用相应训练版本。规则变化时给配置新版本，以便追踪该跑哪些对照。能在同一批样本上替换两个方法并复算指标，就足以检验这处接口是否合用。正式状态和对照由队伍沿依赖图确定后，再逐项迁入 `src/`。
