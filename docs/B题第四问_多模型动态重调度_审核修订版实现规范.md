## 1.3 第四问扰动与评价

- 扰动发生时刻：`t=5` s。
- 新增一条需要两辆车的告警。
- 五辆车中恰好一辆随机故障，各车故障概率相同，即每辆车概率为 `1/5`。
- 故障车辆退出服务，不阻碍其他车辆行驶。
- 通信中断区间：`[5,t_{\mathrm{rec}}]`，其中
  `t_{\mathrm{rec}}\in(5,30]`。
- 通信中断期间车辆继续执行当前已下发任务；新调度指令只能在通信恢复后接收。
- 扰动前已经开始观测的告警视为完成，不能重新调度。
- 已出车但尚未开始观测的车辆允许重新分配。
- `t=0` 制定初始调度时不知道未来扰动；重调度只能在扰动实际发生后触发。
- 评价窗口：按“60秒结束前启动”处理，主实验采用严格条件
  `t_i^{start}<60`。
- 若有待处理告警未能在60秒前启动，令 `t_{\mathrm{last}}=60`。

定义：

``` text
N=\text{评价窗口内需要观测的告警总数}
```

``` text
k=\text{成功启动观测的告警数}
```

``` text
\eta=\frac{k}{N}
```

成功启动的必要条件：同一告警指定的两辆车均到达各自观测站并完成云台指向，之后才启动联合观测。

官方排序：

1.  `\eta` 越大越好；
2.  `\eta` 相同时，`t_{\mathrm{last}}` 越小越好。

# 4. 核心：车辆状态机与事件驱动仿真

这是四种求解方法必须共享的基础模块。先实现并测试状态机，再实现优化器。

## 4.1 车辆状态

每辆车至少维护：

``` text
vehicle_id
position_x, position_y
gimbal_pan_deg
gimbal_tilt_deg
status
current_alert_id
current_station
current_route
route_progress
current_phase_start_time
remaining_phase_time
earliest_available_time
is_failed
```

车辆阶段至少包括：

``` text
IDLE
TRAVELING
SLEWING
READY_WAITING
OBSERVING
RESETTING
FAILED
```

其中：

- `READY_WAITING`：已到站并完成云台指向，但等待同一告警的另一辆车。
- `OBSERVING`：两辆车均已准备就绪，5秒联合观测已经启动。
- `RESETTING`：观测结束，云台正在复位。
- `FAILED`：车辆退出服务。

状态机不能只用一个“空闲/忙碌”二值变量替代。

## 4.2 告警状态

每条告警至少记录：

``` text
alert_id
target_x, target_y, target_z
station_1, station_2
assigned_vehicle_1, assigned_vehicle_2
alert_status
observation_start_time
observation_end_time
is_locked
counted_as_started
```

告警状态至少包括：

``` text
PENDING
ASSIGNED
IN_PROGRESS_BEFORE_DISTURBANCE
STARTED_LOCKED
UNSTARTED_REASSIGNABLE
STARTED_AFTER_RESCHEDULE
UNSTARTED_AT_HORIZON
```

## 4.3 第5秒事件边界规则

必须避免同一时刻的事件处理顺序不确定。

主实验统一采用以下规则：

1.  先处理所有时间戳严格小于5秒的已发生事件。
2.  观测开始时刻严格小于5秒的告警，认定为扰动前已启动，锁定并计为成功。
3.  观测开始时刻恰好等于5秒的告警，按保守规则视为尚未在扰动前启动，先处理扰动，再决定是否启动。
4.  记录故障、告警新增和通信中断事件。
5.  根据是否存在通信中断，确定新指令可生效时刻。

这样可以避免“恰好在第5秒启动”在不同程序中得到不同解释。

## 4.4 已启动告警与车辆释放时间

题目规定扰动前已经开始观测的告警视为完成，不能重调度。

实现时必须区分两个概念：

- **告警计数状态：** 已启动告警计入 `k`，并锁定。
- **车辆物理状态：**
  车辆仍需完成实际剩余操作，不能因告警计数完成就瞬间释放。

例如某告警在4秒启动，扰动在5秒发生：

- 告警已经计为成功；
- 5秒时联合观测尚余4秒；
- 之后仍要完成云台复位；
- 车辆完成复位后才能执行下一任务。

若故障车参与了已启动告警，则故障车立即退出；未故障搭档按照其真实物理状态继续完成剩余过程。故障车不再参与后续任务。

## 4.5 通信中断状态推进

通信中断期间：

- 不允许新任务改派指令生效；
- 正在行驶的车辆继续驶向已经下发的目的站；
- 正在云台转向的车辆继续执行当前转向；
- 已准备就绪的车辆继续等待；
- 正在观测的车辆继续完成当前联合观测；
- 正在复位的车辆继续复位；
- 故障车辆退出服务。

在 `t_rec` 时，读取真实车辆状态快照，再允许车辆接收新的调度指令。

主实验的信息边界约定：

- 新增告警和故障作为场景事件在 `t=5`
  发生，并在事件发生时提供给调度中心用于识别扰动。
- 通信中断限制的是新调度指令向车辆下发/被车辆接收；车辆在恢复前继续执行原已下发任务。
- 调度中心可以在中断期间形成临时计算结果，但不得假定车辆已经执行该临时结果。
- 到 `t_rec`
  时，必须用此时的真实车辆状态重新计算或修复调度，再下发新指令。
- 决策器不得利用未来恢复时刻提前改变车辆任务；只有恢复事件实际发生后才允许新指令生效。

若实现团队认为通信中断也会阻断故障/新告警信息到达调度中心，应另做“事件信息也延迟到恢复时才可见”的敏感性实验，不得与主口径混用。

**纯通信中断情景：** 若没有新增告警和车辆故障，且初始计划已经在 `t=0`
下发，那么车辆继续执行原任务，通信恢复后通常没有需要改变的任务。该情景的动态重调度应允许输出
no-op（不改派），其价值在于验证通信中断本身是否改变既有执行时间轴，而不是强行制造一次任务重排。

## 4.6 已派出但未启动观测的车辆如何重新分配

这类车辆允许重新分配，但必须从当前真实状态接续。

- 行驶中：根据当前路径进度计算实际坐标，从该位置重新计算路径。
- 已到站、尚未指向：记录当前云台角度，按新任务计算转向。
- 正在指向：在恢复时记录当前角度；若取消旧任务，先按当前角度处理新的转向或复位要求。
- 已完成指向、等待搭档：允许重新分配。
- 已开始联合观测：告警锁定，不允许重新分配。

如果车辆需要离开原观测站，必须先满足“行驶时云台保持水平朝东”的规则。若当前云台不在水平朝东姿态，应先计入复位耗时，再开始行驶。若车辆留在原站执行新目标，则从当前姿态计算到新目标的转向时间。

不要把“允许重新分配”错误理解为车辆可以瞬间改变位置、瞬间恢复云台姿态或取消已发生的物理时间。

# 5. 空间可行性与车辆路径

## 5.1 观测站可行性

新告警的观测站必须同时满足：

1.  车辆中心不越界；
2.  车辆圆盘不进入建筑；
3.  视线不被任何建筑遮挡；
4.  云台仰角在 `[-10^\circ,80^\circ]`；
5.  双站位置不同，且交会几何不退化。

车辆半径为1.5 m，因此车辆中心的边界约束为：

``` text
1.5\le x\le98.5,\qquad
1.5\le y\le98.5
```

建筑碰撞检测应采用建筑物与半径1.5
m圆盘的Minkowski膨胀，或采用经过验证的等价几何碰撞检测。不能只检查车辆中心是否位于建筑矩形内部。

若采用多边形近似圆角膨胀，必须使用保守外扩近似，并记录近似误差。

## 5.2 视线遮挡

相机坐标为：

``` text
P=(x_s,y_s,2)
```

目标坐标为：

``` text
T=(x_T,y_T,H)
```

视线参数方程：

``` text
L(\lambda)=P+\lambda(T-P),\quad \lambda\in[0,1]
```

对每个建筑物检查视线线段与建筑物三维棱柱是否相交。任何接触、相切均按遮挡处理。

不能只检查二维线段是否穿过建筑物平面区域而忽略视线高度；必须同时检查交点高度与建筑物高度关系。

## 5.3 云台指向时间

设站点到目标的水平距离为 `r`，相机高度为2 m：

``` text
\alpha=\operatorname{atan2}(H-2,r)
```

方位角为站点指向目标的水平角度 `\beta`。

水平轴旋转角使用最短有符号角差：

``` text
\Delta\beta=\operatorname{wrap}_{[-180^\circ,180^\circ)}(\beta-\beta_0)
```

若当前云台姿态为 `(\beta_0,\alpha_0)`，转向耗时：

``` text
t_{\mathrm{slew}}=
\max\left(
\frac{|\Delta\beta|}{30},
\frac{|\alpha-\alpha_0|}{30}
\right)
```

两轴可以同时转动，所以使用最大值，不使用两者相加。

复位到水平朝东：

``` text
t_{\mathrm{reset}}=
\max\left(
\frac{|\operatorname{wrap}(\beta)|}{30},
\frac{|\alpha|}{30}
\right)
```

注意：如果云台已经处于水平朝东，复位时间为0。

## 5.4 路径规划

车辆中心必须避开膨胀后的建筑物，并处于收缩后的场地边界内。

建议使用：

- 可见图（Visibility Graph）；
- 多边形障碍物膨胀；
- Dijkstra 或 A\* 求最短可行路径。

车辆行驶时间：

``` text
t_{\mathrm{travel}}=\frac{d_{\mathrm{path}}}{3}
```

其中 `d_{\mathrm{path}}` 是可行路径长度，不是默认欧氏直线距离。

如果直线路径本身无碰撞且满足边界约束，可以直接使用直线距离。

所有四种方案必须共享同一套路径长度缓存和路径可行性判定。

## 5.5 时间离散化与数值精度

CP-SAT需要整数时间变量，MILP也应使用相同的时间刻度以便公平比较。

主实验建议采用：

- 基础时间刻度：`Δt = 0.1 s`；
- 观测时长5 s对应50个时间tick；
- 行驶时间、云台转向时间、云台复位时间均向上取整到tick；
- 事件时刻和任务开始时刻用整数tick保存；
- 不得对耗时采用四舍五入后向下缩短操作时间。

例如，某段理论行驶时间为2.31 s，则主模型按2.4
s计入。这样可避免离散模型产生乐观的不可执行时间表。

独立仿真器应同时保留未取整的连续时间计算，用于检查离散化造成的误差。至少对边界情景和代表性情景，使用更细刻度（如0.05
s）重新求解，检查`η`和`t_last`是否变化。

若0.1 s与0.05
s的结果不同，必须报告时间离散化敏感性；不能只选择对结果更有利的刻度。

四种方法必须使用相同的时间刻度、相同的向上取整规则和相同的60秒边界规则。

# 6. 观测站候选配置生成

CP-SAT和MILP需要有限的离散候选配置；ALNS和启发式也必须使用相同候选集，才能公平比较。

## 6.1 原有告警 T1—T3

主实验固定使用第二问（2）最终调度结果中的观测站坐标和站点配对。

原因：第四问以第二问（2）结果为基准。若同时大幅改变原有目标站点，会混淆“站点优化”和“车辆重调度”的效果。

允许车辆重新分配，但主实验不允许任意改变 T1—T3 的站点坐标。

可以另做敏感性实验：允许尚未启动告警重新优化站点，但必须单独标注，不能与主实验混在一起。

## 6.2 新告警 T4

对每个 `(\theta,R,H)`：

1.  计算目标三维坐标。
2.  在车辆中心可行区域内生成站点候选点。
3.  检查车辆几何约束、视线遮挡和云台仰角。
4.  计算各车辆到候选站点的可行路径。
5.  构造不同站点对。
6.  计算基线长度、交会角和第二问（1）采用的定位精度指标。
7.  删除几何退化或不符合第二问既定精度可行性规则的站点对。
8.  对候选站点对做非支配筛选，保留时间效率与定位几何质量之间的代表性折中方案。

建议先采用1
m网格生成可行站点，再对优质候选进行局部细化。候选数量过大时，可以按“车辆对—站点对”组合进行Pareto筛选。

**重要：**
候选数上限、网格步长和局部细化精度必须写入配置文件，并做敏感性实验。不能只保留最快的几个站点而把定位精度很好的候选全部删掉。

若第二问（1）没有确定明确的交会角阈值，不要在第四问临时随意指定一个阈值。应复用第二问的精度评价规则；若仍没有数值可行标准，则至少排除数值退化的近共线配置，并报告交会角和精度指标，进行阈值敏感性分析。

# 7. 统一数学优化问题

设告警集合为 `I`，可用车辆集合为 `V`。

对每条告警 `i`，定义：

``` text
y_i=
\begin{cases}
1,&\text{告警 }i\text{ 在60秒前成功启动}\\
0,&\text{否则}
\end{cases}
```

已在扰动前启动的告警固定 `y_i=1`，并锁定其分配，不进入重调度决策。

每条未启动且被安排的告警必须选择：

- 两辆不同车辆；
- 一个合法双站配置；
- 两辆车各自的任务执行顺序；
- 对应的路径和时间。

核心分配约束：

``` text
\sum_{v\in V}x_{iv}=2y_i
```

其中 `x_{iv}=1` 表示车辆 `v` 被分配给告警 `i`。

实际实现建议使用“服务配置”变量。一个服务配置至少包含：

``` text
alert_id
vehicle_1
station_1
vehicle_2
station_2
station_pair_id
```

服务配置必须保证两辆车不同，两个站点合法且几何不退化。

每条成功告警选择且只选择一个服务配置。

## 7.1 双车同步

对告警 `i`，两辆车分别完成行驶和指向后的准备时间为：

``` text
r_{iv_1},\quad r_{iv_2}
```

联合观测启动时间必须为：

``` text
S_i=\max(r_{iv_1},r_{iv_2})
```

两辆车均在 `S_i` 开始联合观测，观测持续5秒：

``` text
E_i=S_i+5
```

每辆车完成复位后才能执行下一任务：

``` text
A_{iv}=E_i+t^{reset}_{iv}
```

车辆较早到站时需要等待另一辆车；等待期间仍占用该车辆，不能分配给其他告警。

## 7.2 车辆任务互斥与路径顺序

同一辆车不能同时承担两个任务。

若车辆 `v` 先执行告警 `i`，再执行告警 `j`，必须满足：

``` text
D_{jv}\ge A_{iv}+t^{travel}_{v,i\rightarrow j}
```

其中：

- `A_{iv}`：车辆完成告警 `i` 观测和复位、可离站的时刻；
- `D_{jv}`：车辆前往告警 `j` 的出发时刻；
- `t^{travel}_{v,i\rightarrow j}`：从前一站点到后一站点的可行路径行驶时间。

第一项任务的出发时间由扰动时刻的车辆实时状态决定，不得统一从初始位置重新计算。

## 7.3 通信约束

无通信中断：

``` text
t_{\mathrm{dispatch}}\ge5
```

存在通信中断：

``` text
t_{\mathrm{dispatch}}\ge t_{\mathrm{rec}}
```

通信恢复前，所有车辆只执行已经下发的任务。

## 7.4 官方字典序目标

第一阶段：

``` text
\max k=\sum_{i\in I}y_i
```

第二阶段固定第一阶段最优值：

``` text
k=k^\*
```

若 `k^\*=N`：

``` text
\min t_{\mathrm{last}}
```

并满足：

``` text
t_{\mathrm{last}}\ge S_i,\quad\forall i\in I
```

若 `k^\*<N`，按官方规则：

``` text
t_{\mathrm{last}}=60
```

此时官方两个指标可能无法区分不同方案。允许增加辅助目标，例如：

``` text
\min \sum_{i:y_i=1}S_i
```

再进一步最小化相对原计划的改动量。

辅助目标不得改变官方 `(\eta,t_{\mathrm{last}})` 排名。

## 7.5 时间窗口边界

主实验采用：

``` text
S_i<60
```

恰好在60秒启动不计为成功。

对原题英文文本中 `[0,60]`
的端点表达，采用“60秒结束前启动”的保守口径，并在报告中明确说明。若需要，可另做
`S_i\le60` 的边界敏感性对照，但不能混用两种口径。

# 8. 四种并行求解方案

四种方案使用相同的服务配置集合、车辆状态快照、路径缓存、时间精度、硬约束和官方评价器。

## 方案 A：CP-SAT 精确约束规划

工具：Google OR-Tools CP-SAT。

建模内容：

- 每条告警选择一个服务配置，或不安排；
- 每个服务配置包含两辆不同车辆及对应站点；
- 每辆车的任务序列用前驱/后继弧或等价序列变量表示；
- 对每个任务建立车辆占用区间；
- 任务区间包含出发、行驶、等待、指向、联合观测和复位；
- 同一车辆任务区间不得重叠；
- 通过共同启动变量实现双车同步；
- 用序列相关转移时间处理不同站点之间的行驶；
- 用扰动时刻状态快照约束第一项后续任务。

实现建议：

- 可使用 Optional Interval、NoOverlap、AddCircuit 和 OnlyEnforceIf
  等约束构造。
- 对双车共同启动时间显式建立 max 关系，不得仅靠输出后处理猜测。
- 车辆任务占用区间应从其离开当前状态开始，直到完成该任务复位后释放。
- 已启动任务作为固定前缀或固定状态，不重新选择车辆。
- 采用两阶段求解实现字典序目标。

结果状态必须区分：

- `OPTIMAL`：求解器证明当前离散模型最优；
- `FEASIBLE`：找到可行解，但没有证明最优；
- `INFEASIBLE`：证明模型不可行；
- `UNKNOWN`：未能判定。

只有 `OPTIMAL` 才能声称在当前离散模型下获得最优解。

## 方案 B：MILP 混合整数线性规划

工具优先顺序：

1.  项目可用的 Gurobi；
2.  若没有可用许可证，使用 SCIP 或其他可用 MILP 求解器。

MILP与CP-SAT必须表达同一调度问题。

主要变量：

- `y_i`：告警是否成功启动；
- 服务配置选择二元变量；
- 车辆任务分配变量；
- 车辆任务先后顺序变量；
- 车辆出发、到站、指向完成、观测开始、观测结束、复位完成时间；
- 双车同步启动变量；
- 用于线性化 max 和条件约束的辅助二元变量。

必须正确线性化：

- 双车准备时间的最大值；
- 车辆任务先后关系；
- 车辆路径转移时间；
- 未选服务配置对应的时间变量；
- 故障车辆禁用；
- 通信恢复前不得执行新指令。

Big-M必须根据60秒评价窗口和最大合理操作时间给出紧致上界，不能任意取极大值。

MILP也采用两阶段字典序求解。

只有求解器证明最优或报告足够小且明确的MIP
gap时，才能声称达到相应精度下的最优；时间限制下仅有 incumbent
时，必须标记为可行解。

## 方案 C：事件触发 ALNS 增量修复

名称：Event-Triggered Adaptive Large Neighborhood Search。

它从第二问（2）原调度及扰动时刻的车辆状态出发，重点修复受影响任务，不必完全推翻原计划。

### 破坏算子（Destroy）

至少实现：

1.  故障关联任务移除；
2.  新增告警相关任务插入前的局部移除；
3.  随机移除若干未启动任务；
4.  移除预计造成最大等待的任务；
5.  移除高冲突车辆上的任务；
6.  移除站点配置不利的任务。

### 修复算子（Repair）

至少实现：

1.  最佳可行双车插入；
2.  Regret-2 插入；
3.  最少可行车辆对优先插入；
4.  站点配置与车辆组合联合插入；
5.  保持部分原任务顺序的修复。

### 局部搜索

至少实现：

- 车辆对交换；
- 任务重新插入；
- 两辆车的任务顺序交换；
- 任务对调；
- 站点配置替换；
- 路径顺序的局部优化。

### 接受准则

始终维护一个最优可行解。

评价采用字典序：

``` text
(-k,\ t_{\mathrm{last}},\ \text{辅助代价})
```

不允许接受一个官方主目标更差的方案作为最终 incumbent。

为避免搜索停滞，可以在相同主目标层级内对辅助代价使用模拟退火或随机接受，并保留全程最优解。

ALNS至少使用10个随机种子运行，记录每次结果、耗时和随机种子。若算力允许，使用20个种子。

**不要把ALNS的最好一次结果当成稳定性能；同时报告最好值、中位数、最差值和标准差。**

## 方案 D：双车配对与增量插入启发式

该方案作为简单、透明的基线求解器。

建议采用：

1.  生成所有可行告警—车辆对—站点配置；
2.  按可行配置数量从少到多排列待处理告警，优先处理最难安排的告警；
3.  对每条告警枚举可行车辆对和可行插入位置；
4.  使用统一仿真器评估插入后的全部车辆时间轴；
5.  按官方字典序选择最优插入；
6.  依次处理其余告警；
7.  执行少量车辆对交换、任务重插入和顺序调整。

选择车辆对时不能只比较两辆车各自的距离和。应比较：

``` text
\max(r_{iv_1},r_{iv_2})
```

并考虑该车辆组合对其他待处理告警的机会成本。

该方案必须完全确定化，固定并记录所有平局规则和随机种子。

# 9. 保留原调度基线：必须采用统一、可复现的定义

官方要求与“保留原调度”策略比较，但没有进一步规定新增告警的所有追加规则。因此采用以下主基线，并做敏感性对照。

## 9.1 主基线：原任务不重排 + 新告警仅追加

规则：

1.  T1—T3原有车辆分配、观测站和任务顺序保持不变。
2.  故障车辆退出服务。
3.  原任务若因故障缺少一辆车，不允许其他车辆替补。
4.  新增T4不能插入或改变任何原有任务的开始时间、车辆分配和任务顺序。
5.  T4只允许使用不影响原计划的空闲资源追加执行。
6.  若不能在60秒前由两辆可用车辆共同启动，则T4记为未启动。
7.  通信中断期间不下发追加任务；恢复后才允许执行追加任务。
8.  原计划中已启动的告警仍按题意计为完成。

“追加”不得导致任何原有告警延迟。如果追加任务与原计划冲突，则该追加方案不合法。

## 9.2 敏感性基线：严格冻结

严格冻结版本不为T4安排任何新任务，只让原计划继续执行，故障车辆退出。

这可以展示“完全不调整”与“允许追加但不改变原计划”之间的差异。

主论文应明确使用哪一个作为主基线，不得在不同情景中临时切换规则。

# 10. 扰动情景设计与实验数量

## 10.1 新增告警基础情景：72个

采用：

``` text
\theta\in\{0^\circ,15^\circ,\ldots,345^\circ\}
```

共24个方位角。

``` text
R\in\{30,40,50\}\text{ m}
```

高度固定：

``` text
H=50\text{ m}
```

因此：

``` text
24\times3=72
```

个基础情景。

采用0°至345°，不重复360°。

### 临界情景补充

72个基础情景不能保证捕获所有由建筑遮挡造成的狭窄可行区域。完成基础实验后，按以下指标自适应补充情景：

- 可行观测站数量突变；
- 可行双站配置数量接近0；
- 交会角或定位精度明显恶化；
- 可用车辆对数量突变；
- `\eta` 或 `t_{\mathrm{last}}` 随方位角/距离出现明显跳变。

在上述变化区间加密方位角或距离采样，并把补充情景单独标记为
`critical_refinement`。

## 10.2 车辆故障

五辆车逐一故障：

``` text
F=\{V1,V2,V3,V4,V5\}
```

每种概率均为 `1/5`，必须全部枚举。

故障维度可以计算等概率加权结果：

``` text
E[\eta]=\frac{1}{5}\sum_{v=1}^{5}\eta_v
```

不得只模拟一辆故障车。

## 10.3 通信中断

主实验选取：

| `t_{\mathrm{rec}}` | 从5秒起算的中断时长 |
|-------------------:|--------------------:|
|               10 s |                 5 s |
|               20 s |                15 s |
|               30 s |                25 s |

**原题存在表述不一致：** 一处给出
`t_{\mathrm{rec}}\in(5,30]`，另一处称中断时长在\[5,30\]秒。若中断从5秒开始且
`t_{\mathrm{rec}}\le30`，实际最大中断时长为25秒。

主实验优先遵循明确的 `t_{\mathrm{rec}}`
区间，报告实际中断时长，并在论文中说明该解释。不要为了凑足30秒中断而把恢复时刻擅自设为35秒。

## 10.4 七类情景及基础数量

| 编号     | 扰动类型            |    组合数量 |
|----------|---------------------|------------:|
| E1       | 仅新增告警          |          72 |
| E2       | 仅车辆故障          |           5 |
| E3       | 仅通信中断          |           3 |
| E4       | 新增告警 + 故障     |    72×5=360 |
| E5       | 新增告警 + 通信中断 |    72×3=216 |
| E6       | 故障 + 通信中断     |      5×3=15 |
| E7       | 三种扰动同时发生    | 72×5×3=1080 |
| **合计** |                     |    **1751** |

临界情景补充数量另计。

新告警没有官方给定的概率分布，因此72个情景的等权平均只能称为“代表性情景集平均值”，不能称为真实概率期望。

故障车具有明确等概率，可以计算故障维度的概率加权统计。

通信恢复时刻同样没有给出概率分布，三个恢复时刻的等权平均也只能称为情景集平均。

## 11.2 计算资源与运行限制

- 记录CPU型号、内存、操作系统、求解器版本。
- 记录每个模型的线程数、时间限制和随机种子。

建议先用少量情景进行性能测试，再确定正式时间预算。时间预算写入统一配置文件，不要散落在代码中。

ALNS参数、候选站点筛选参数和启发式规则只能在开发情景中调整。

最终测试情景不能用于反复调参。

# 12. 独立离散事件仿真验证器

这是全项目最重要的质量控制模块。

四种优化器输出计划后，仿真器必须从扰动时刻的车辆状态重新执行计划，而不是直接相信求解器输出的时间变量。

## 12.1 仿真器输入

``` text
scenario
vehicle_state_snapshot
alert_state_snapshot
selected_service_configurations
```

## 12.3 必须检查的硬约束

- 车辆路径不越界、不穿建筑；
- 观测站满足空间可观测条件；

## 12.4 独立性要求

若仿真器重算时间与优化器预测时间存在差异：

1.  定位差异事件；
2.  检查时间取整、路径长度、同步等待和复位；
3.  修正模型或将方案判为无效；
4.  保存验证日志。

# 13. 统一评价、排名和模型选择

## 13.1 官方指标

对每个情景、每个模型和每种策略分别计算：

- `N`：需要观测的告警总数；
- `k`：成功启动数量；
- `\eta=k/N`；
- `t_{\mathrm{last}}`。

若所有告警均在60秒前启动：

``` text
t_{\mathrm{last}}=\max_i S_i
```

若存在任一待处理告警未在60秒前启动：

``` text
t_{\mathrm{last}}=60
```

扰动前已经启动的告警计入 `k`，其实际启动时间也参与最晚启动时刻统计。

## 13.2 方案排名

按以下顺序比较：

1.  硬约束验证通过；
2.  `\eta` 更大；
3.  `\eta` 相同则 `t_{\mathrm{last}}` 更小；
4.  官方指标相同，比较成功任务启动时间总和；
5.  再比较相对原计划的改动量；
6.  再比较求解时间和稳定性。

第4—6项只能作为辅助决策指标，不能改变官方排名。

## 13.3 精确算法与启发式的结论口径

- CP-SAT/MILP状态为 `OPTIMAL`：可称当前离散候选模型下达到最优。
- 状态为 `FEASIBLE`：只能称找到可行解。
- ALNS/贪心：只能称找到高质量或当前最好可行解，不能声称全局最优。
- 不同算法若官方指标相同，应进一步比较最优性证明、计算时间、稳定性和调度改动量。
- 若所有精确算法均未证明最优，报告当前最好可行解和最优界，不得写成“最优方案”。

# 18. 最终方法选择原则

最终不预先指定胜者。

按以下原则选择：

- 若CP-SAT能在大多数情景快速证明最优，优先作为主模型。
- 若MILP能独立得到相同结果并证明最优，作为强交叉验证。
- 若精确求解在少数情景超时，比较ALNS的可行解、最优界和运行时间。
- 若简单启发式已经达到精确模型的官方指标，则应报告其效率优势，不人为夸大复杂模型价值。
- 若不同模型得到相同
  `(\eta,t_{\mathrm{last}})`，再比较辅助指标、稳定性和调度改动量。
- 若所有精确模型均未证明最优，只能报告当前最好可行方案，不得称为全局最优。

**核心原则：模型由题目约束决定，算法由模型规模和求解效果决定，最终结论由独立仿真和可复核数据决定。**
