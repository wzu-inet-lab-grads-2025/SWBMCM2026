# C 题预处理与特征口径

每次比较应能从一行汇总结果追溯到数据版本、环境划分、记录数、合格点或窗数、排除原因、特征版本及其可见时刻。这里记录已核对口径和待检验的候选，用于当前 worktree 的探索。[数据核查](../research/C题数据首轮核查.md) · [队伍决定](decisions.md)

## 从原始记录到可评分样本

| 环节 | 输入及处理 | 检验与当前限制 |
|---|---|---|
| 身份与划分 | 用内部 `episode_uuid` 连官方划分，目录 `sample` 只用于找文件。先按官方环境划分，再在单条记录内构造相邻对、片段和窗口。 | 每条记录唯一对应一个环境与 split。核对环境、场景和操作员交集，输出每种来源的保留及排除数。测试只在方案冻结后评价。 |
| 时间对齐 | CSV 保留 `header.ts` 整数纳秒，先相减再换秒。Demo 使用存储的相对秒和帧索引。保留原序，检查重复、倒序、左右手/标签对齐和长间隔。 | Q1/Q2 探索以相邻间隔大于 50 ms 为连续段断点。Q3 按标注起点计算源前缀，0.2/0.6/1.0 的闭边界按真实采样判断。保留纳秒边界反例。 |
| 通道、坐标与单位 | 左右手各自第 0 点 XYZ，保留手别和本记录坐标系。检查有限值及全零点。 | Demo 关节名给出腕点，CSV 同序映射与长度单位仍待字段字典核验。各记录的原点独立。换算厘米、跨记录合并绝对方向或位置前应提供坐标依据。 |
| 质量与缺失 | 区分数值缺失、显式正常、显式标坏、稀疏未列、仅另一手标坏。联合坏标记适合研究“至少一只手”；涉及哪只手时使用可定位原因。 | Q2 的保守评分池要求整窗显式正常且双腕合格。Demo 稀疏未列记未知并单报。Q3 按规程披露原始缺失与坏标，特征程序才作处理。 |
| 三种分母 | Q1 统计记录、时刻和连续事件。Q2 从合格段构造历史加遮挡窗并报告每手评分时刻。Q3 分开记录时长资格、特征可用率及可执行作业。 | 首轮 Q2 验证有 5,259 个合格时刻、50 个不重叠窗、每手 2,989 个评分时刻。Q3 的 343 个长度合格片段仍可能含坏帧。 |

合成时钟和缺失样例可用 `python -B -m unittest checks.test_c_preprocessing` 运行。按时间拼表的检验精确到纳秒，腕点检查区分单轴为零与整个三维点为零。[合成用例](../checks/test_c_preprocessing.py)

按环境报告时分列官方记录总数、满足参考条件的记录数和可评分时刻数。处理坏段时，在记录边缘和断点处分段，分别标注起点是否可见、恢复是否可见。对无法观察起点的坏段，保留其恢复证据。共享划分和各问接口见[迭代架构草案](C题迭代架构草案.md)。

## 特征可见性与检验

| 候选或已有特征 | 计算所需信息 | 可验证的问题 |
|---|---|---|
| Q1 上一次质量标记 | 预测下一采样的联合坏标记时只用此前已返回的显式标记，同记录连续相邻对。 | 分开统计坏段起点、持续和恢复。坏事件少的环境保留原分母，无正例时召回记为不可估。训练对照见[转移计数](../research/C题质量预警训练核对.md)。 |
| Q1/Q2 近期运动 | 执行在线预测时只用已获得的同手 XYZ 和相应真实时差。位移、速度或双腕相对位置应标注历史长度、单位、有效点/点对数和最近有效采样时刻。 | 两点间的时差必须为正。报告特征可用率、不可用时如何退回基线。比较历史运动与保持最近值时共用同一批窗和参考点。未来平滑结果若用于离线描述，单列用途。 |
| Q2 距上次可靠观测的时长 | 用当前决策时刻减最近**已返回观测的源时刻**。固定窗评估的横轴另用距遮挡前最近可靠点的时间，方便配对。 | 修改尚未返回的腕点，其数值及衍生特征都应保持不可见。到期后同时披露左右腕，使用源时间并保留已提交预测。 |
| Q3 类别与腕部前缀 | 已释放的作业族，及当前披露范围内逐腕首末位移、连续有效点间路径长度除以实际时间。缺失指示与填补/缩放参数来自训练。 | 按来源、前缀档和片段报告保留率。在同片段上对比仅作业族与增加前缀；检查跨档增长、前缀右端点、未返回后缀扰动、训练变换在验证上复用。[配对验证](../research/C题腕部前缀岭回归验证.md) |
| 任务、阶段、场景 | 文本描述覆盖整个标注区间，P/A/L 有作业族含义。环境用于分组与留出。 | 逐帧阶段研究需有可复核的标注或代理定义。Q3 当前决策仅可读取公开的作业条件与已返回信息。源目录、片段终点、采样种子、完整文本只在对应离线核查中使用。 |

比较新特征时，先登记一个能推翻它的观察，再记训练分母、无特征基线、同窗或同片段的配对差与按环境波动。覆盖不足时同时报告全池表现和共同可评分子集。由队伍决定保留的特征、变换参数、缺失回退及适用范围，再随正式代码进入 `src/`。
